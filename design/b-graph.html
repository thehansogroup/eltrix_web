Eltrix Matrix homeserver · Elixir/OTP plate 1 of 1 — room event graph

A room is a graph. So is this.

Every message is a signed event pointing at the events before it. Nothing here is a diagram of the idea — these are events, with their real IDs, in the order they were accepted.

Two branches, one head. State resolution v2 decides which wins, and the answer does not depend on the order they arrived in — asserted by a property test over every permutation.

What descends from it

Federationverified

Live with Synapse 1.157, both directions, behind an allowlist that is closed by default. Inbound events are verified against the sender's server, not the transaction origin.

End-to-end encryptionverified

Cross-signing signatures are verified rather than merely attributed. Key backup restores.

Room versions 10, 11, 12verified

Redaction checked against 40 real v10 state events from a production server. 40/40 on IDs, hashes and signatures.

Spaces, threads, search, pushpartial

All four work against Element. None has a conformance run, so none is called done.

VoIP, SSO, 3PID, appservicesnot built

Every one answers 404 M_UNRECOGNIZED, so a client detects the absence instead of failing on it.

Presence is missing deliberately. It is the largest source of federation traffic on the network and the least load-bearing feature on it, so /presence returns 404 and clients degrade.
